# 🤖 AGENT WORK RULES (에이전트 작업 수칙)

이 문서는 AI 에이전트가 사용자와 협업할 때 반드시 준수해야 할 최상위 행동 수칙을 정의합니다.

## 1. 작업 개시 및 승인 절차
- **컴파일 에러 수정**: 사용자가 컴파일 에러 메시지를 직접 전달한 경우에 한해, 별도의 승인 절차 없이 즉시 수정하고 결과를 보고합니다.
- **그 외 모든 작업**: 
    - 반드시 `Implementation Plan`(작업 계획서)에 상세 내용을 명시해야 합니다.
    - 사용자가 내용을 검토한 후 **`[Proceed]`**라고 명시적으로 답변한 경우에만 실제 코드 수정을 시작합니다.

## 2. 언어 및 소통
- 사용자와의 **모든 대화, 알림(Notification), 그리고 모든 문서(Artifacts)는 반드시 '한국어(Korean)'**를 사용합니다.

## 3. 코드 보호 및 강제 중단
- 작업을 수행하는 도중 코드 내에 **`수정 금지`** 또는 **`Modification Prohibited`**와 같은 명시적인 보호 문구가 있는 영역을 발견할 경우, **즉시 모든 작업을 중단**하고 사용자에게 보고합니다.

## 4. 규칙 준수 확인
- 에이전트는 매 세션 및 작업 시작 전 이 가이드를 다시 한 번 숙지하여 사용자의 작업 스타일과 안전 수칙을 철저히 따릅니다.

## 5. 배포 및 커밋 원칙 (Local First)
- **선 로컬 검증, 후 원격 반영**: 모든 변경 사항은 로컬 환경(`npm run dev` 등)에서 충분히 검증한 후, 사용자의 명시적인 요청이나 확신이 있을 때만 GitHub(Remote)에 푸시합니다.
- 잦은 커밋/푸시로 인한 혼란을 방지하고 작업의 안정성을 확보하기 위함입니다.

## 6. 지도 엔진 보호 정책 (Map Engine Protection)
- **전체 리팩토링 금지**: `Apple`, `Google`, `Naver`, `Kakao` 등 4대 지도 엔진의 핵심 클래스들을 **한 번의 태스크로 동시에 대규모 리팩토링하는 행위를 엄격히 금지**합니다.
- **개별 접근**: 기능 추가나 버그 수정 시 반드시 하나의 엔진 단위로 검증을 마친 후 다음 엔진으로 이동해야 합니다. 이는 각 엔진별로 미세하게 조정된 핀 앵커 및 오프셋 데이터의 파손을 막기 위함입니다.

## 7. 코드 아키텍처 원칙 (No Inheritance)
- **상속 자제**: 새로운 코드를 작성할 때 가능하면 **클래스 상속(Inheritance) 코드를 만들지 않습니다.** 
- 대신 프로토콜(Interface), 구조체(Struct), 또는 독립적인 함수들을 활용하여 기능을 조합하는 방식을 우선합니다. 이는 코드의 결합도를 낮추고 유지보수 및 AI의 코드 이해도를 높이기 위한 원칙입니다.
