# Map Begin Logic (맵 시작 시퀀스 설계 가이드)

본 문서는 AllToDo 앱 실행 시 지도가 표시되는 정교한 **3단계 시퀀스(Map Begin Logic)**와 그 기술적 구현 상세를 정의합니다. 모든 맵 공급자(Google, Kakao, Naver)는 이 로직을 일관되게 따라야 하며, 사용자에게 "지연 없는 부드러운 시작 경험"을 제공하는 것을 목표로 합니다.

---

## 0. 핵심 상태 관리

### 0.1 Before Location (직전 위치)
- **개념**: 앱이 항상 기억하고 있는 "마지막 유효 위치"입니다. 맵 엔진 로딩 전 즉각적인 시각 정보 제공을 위해 필수적입니다.
- **저장/로드**: `SharedPreferences`에 1:100,000 스케일의 정수 또는 Float 형태로 저장됩니다.
- **기본값**: 데이터가 없으면 **광화문(37.5759, 126.9768)**을 사용합니다.

### 0.2 Continuous Snapshot (상시 스냅샷)
- **개념**: 포그라운드에서 핀 데이터(`clusteredItems`)가 변경될 때마다 그 좌표 목록을 메모리에 상시 캐싱합니다.
- **용도**: 백그라운드에서 복귀 시, ViewModel의 데이터 로딩이나 Flow 방출을 기다리지 않고 **즉시 2단계(영역 맞춤)를 수행**할 수 있게 하여 "Zero-Wait Resume"을 실현합니다.

---

## 1단계: 초고속 지도 표시 (Fast Display)

- **시점**: 맵 컴포넌트(`NaverMapContent`, `KakaoMapContent`, `GoogleMapContent`)가 화면에 처음 그려지는 첫 프레임.
- **목표**: 지도가 뜨자마자 유저가 알고 있는 익숙한 장소를 보여주어 "앱이 즉시 준비됨"을 인지시킴.
- **동작**: 
    - 맵 엔진의 초기 카메라 설정을 `beforeLocation` 및 **줌 15.0**으로 강제 고정합니다.
    - 코드를 통한 카메라 이동(`animate`)이 아닌 **초기 설정(`initial position`)**을 통해 렌더링 시작부터 해당 위치를 보여줍니다.

---

## 2단계: 최적 영역 표시 (Fit-Bounds Display)

- **시점**: 1단계 직후, 또는 백그라운드 복귀 시 즉시.
- **기술적 핵심**: **Integer-based Fast Bounds Calculation**

### 2.1 정수 기반 영역 계산 (Optimization)
맵 엔진(SDK)의 무거운 영역 계산 로직을 바이패스하고 CPU 레벨에서 즉시 계산합니다.
1.  **정수화**: 모든 위경도 좌표에 **100,000**을 곱하여 정수로 변환합니다. (약 1.1m 정밀도)
2.  **영역 산출**: 수집된 정수 좌표들의 `minLat, maxLat, minLon, maxLon`을 구합니다.
3.  **여백 추가 (Padding)**:
    - 계산된 영역의 가로/세로 길이에 각각 **1/4 (25%)** 만큼의 여백을 상하좌우에 추가합니다.
    - `finalMinLat = (minLatInt - padLat) / 100,000.0` 방식으로 최종 좌표를 도출합니다.
4.  **분기 및 이동**:
    - **500km 필터링 (Sanity Check)**: 너무 멀리 있는 핀은 영역 계산에서 제외하여 "태평양 줌아웃" 현상을 원천 차단합니다.
    - **Small Area (줌 15 이내)**: 영역 크기가 **1,500 units** (줌 15 표준 스팬)보다 작으면, 영역 중심점으로 **줌 15.0으로 즉시 이동**합니다.
    - **Large Area**: 계산된 `finalBounds`를 엔진에 전달합니다.
    - **Raw Pin Display**: 이 단계에서 **클러스터링을 비활성화**하여 개별 핀(Raw Pins)을 모두 노출합니다. 사용자가 전체 분포를 파악할 수 있도록 **3초간 대기**합니다.

### 2.2 줌 락 전략 (Zoom Lock Strategy)
- **문제**: 핀들이 촘촘할 경우 SDK가 자동으로 줌 18~20까지 들어가는 "과도한 줌인" 현상 발생. 
- **해결**: 2단계 수행 직전, 맵 엔진의 **최대 줌 제한(`Max Zoom`)을 15.0으로 즉시 잠급니다.**
- **효과**: 애니메이션 도중 줌 레벨이 15.0을 절대 넘지 않아 전체적인 지형 맥락을 유지합니다.

---

## 3단계: 최종 위치 정착 및 테더링 활성화 (Final Focus & Tethering)

- **시점**: 2단계 영역이 표시된 후 **3초** 경과 시.
- **목표**: 전체 맥락 파악 후 사용자의 현재 위치로 정밀하게 포커싱(Zoom-in)하며, 이후의 스마트 테더링을 위한 앵커를 설정.
- **동작**:
    1.  **클러스터링 활성화 (Clustering ON)**: 초기에는 모든 핀을 개별적으로 보여주었으나(Stage 2), 이 시점에 **클러스터링 모드를 활성화**하여 시각적으로 정리합니다.
    2.  **줌 릴리즈 & 이동 (Zoom to 18)**: 2단계 줌 락을 해제하고, 사용자의 실시간 좌표(`currentLocation`)를 향해 **줌 18.0**으로 부드럽게 이동합니다.
    4.  **앵커 초기화 (Anchor Initialization)**: 이동이 시작/완료되는 시점에 현재 위치를 **스마트 테더링 앵커(`moveLocation`)**로 저장합니다. 이 앵커는 사용자가 조작하여 멀어지기 전까지 지도가 따라와야 할 기준점이 됩니다.
    5.  **성공 플래그**: `initialAnimationDone`을 `true`로 설정하여 시퀀스를 공식 종료하고 상시 테더링 모드로 전환합니다.

## 4. 백그라운드 복귀 강화 (Resume Logic)

### 4.1 5초 룰 (5-Second Rule)
- 앱이 백그라운드로 간 지 **5초 이상** 경과 후 복귀하면, 지도의 현재 상태가 최신 위치와 괴리되었을 가능성이 높다고 판단합니다.
- **데이터 갱신**: `updateFilteredItems(immediate=true)`를 호출하여 `+/- 24시간` 기준 데이터를 즉시 갱신합니다.
- 이 경우 초기화 시퀀스 플래그를 리셋하여 유저에게 다시 1단계부터의 브리핑(1단계 ➡️ 2단계 ➡️ 3단계)을 제공합니다.

### 4.2 Zero-Wait Resume
- 복귀 시점에 로컬 캐시된 스냅샷이 있다면, ViewModel의 데이터 로딩을 대기하지 않고 즉시 2단계(정수 기반 영역 맞춤)를 수행합니다. 
- 이를 통해 유저는 앱을 켜자마자 지도 영역이 샥- 바뀌며 내 주변 상황을 요약받는 "Zero-Wait" 경험을 얻게 됩니다.

---

## 💎 부록: 정수 연산 가이드라인
- **Precision**: `100,000` (Deg to Int scaling)
- **Zoom 15 Threshold**: `1,500 units` (Approx. 1.5km spread)
- **Padding Factor**: `0.25` (1/4 of span)
