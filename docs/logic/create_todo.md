#할 일 만들기 (Create Todo) 구현 명세 및 로직

## 1. 개요
지도의 특정 지점을 길게 눌러 새로운 할 일을 생성하는 기능입니다. 맵 SDK(네이버, 카카오, 구글)와 연동되어 위치 정보를 정확히 캡처하고, 하단 레이어를 통해 세부 정보를 입력받습니다.

## 2. 주요 로직 및 흐름

### A. 트리거 (Long-press)
- **동작**: 지도 위 임의의 지점을 롱터치(Long-click)하면 시작됩니다.
- **맵 상태 변화**:
    - `isCreatingTodo` 상태가 `true`로 변경됩니다.
    - 선택한 좌표에 **녹색 할일핀(pin_todo_ready)**이 생성됩니다.
    - **뷰포트 오프셋 설정**: 하단 입력창이 맵의 하단을 가리므로, 맵 SDK의 `Padding` 기능을 사용하여 실제 동작 영역을 지도의 상단 절반으로 제한하고, 핀이 그 중앙에 위치하도록 카메라를 이동합니다.

### B. 컨텍스트 트리거 (Callout Center Click)
- **동작**: 기존에 생성된 핀(할 일 또는 히스토리)의 물풍선을 터치하고, 중앙의 정보 영역(이름/시간)을 클릭하면 해당 정보를 바탕으로 할 일을 생성합니다.
- **자동 입력**: 
    - 클릭한 항목의 이름(`todo_name`)이 입력창에 미리 채워집니다.
    - 좌표가 해당 항목의 위치로 고정됩니다.
- **동적 타이틀**:
    - 일반 롱터치 시: **"할 일 만들기"**
    - 물풍선 트리거 시: **"할 일"**

### B. 입력 레이어 (CreateTodoLayer)
- **위치**: 화면 하단 70% 영역을 차지하는 오버레이 창입니다. (시인성 확보를 위해 기존 50%에서 확장)
- **입력 항목**:
    - **시각적 가시성**: 입력 필드의 텍스트 색상은 **Gray 9 (`#212121`)**, 예시(Placeholder) 텍스트는 **Gray 7 (`#616161`)**을 사용하여 표준적인 대비를 유지합니다.
    - **상단 여백**: (할 일 이름), (연락처 검색), (메모) 입력창이 열릴 때, 화면 상단으로부터 **24dp**의 여백을 추가하여 시각적 답답함을 해소했습니다.
    - **자동 포커스**: 창이 열리면 즉시 키보드가 활성화되어 바로 입력을 시작할 수 있습니다.
    - **표시 규칙**: 할 일(Todo)은 **현재 시점 기준 +-24시간 이내**의 항목만 노출됩니다.
    - **디버깅 로그**: 로그 형식을 **`(현재 시간) " >>> " [카테고리] 내용`**으로 통일하고, 핀 종류별 개수를 구분하여 출력합니다.
        - 앱 시작 시: `22:38:01  >>>  [App Start] Total DB Todos: 5`
        - 지도 표시 시: `22:38:05  >>>  [Map Display] Total Pins: 5 (Filtered Todos: 1, Filtered History: 2)`
    - **즉시 표시 로직**: 등록 시 지도의 핀을 즉시 갱신합니다.
    - **같이 할 사람**: 라벨 색상 Gray 7. **전체 화면** 연락처 검색 및 선택 기능을 제공합니다.
    - **메모**: 라벨 색상 Gray 7. **전체 화면** 입력창과 추천 리스트를 제공합니다.
    - **초기값 세팅**: `initialName` 파라미터를 통해 진입 소스에 따른 초기 할 일 이름을 유연하게 설정 가능합니다.

### C. 데이터 저장 (TodoViewModel)
- **엔티티 확장**: `TodoItem`에 `person`, `targetDate`, `targetTime`, `memo` 필드가 추가되었습니다.
- **추천 시스템**: `loadTodos` 수행 시 `distinct().take(3)` 로직을 통해 최근 사용된 이름과 메모를 실시간으로 업데이트하여 UI(StateFlow)에 전달합니다.

## 3. 테스트 및 문제 해결 기록 (Issue Tracking)

### [2025-12-22] 초기 구현 및 통합 테스트
- **이슈 1: 맵 오프셋 적용 시점**
    - **현상**: 롱터치 직후 입력창이 맵 하단을 가리면서 핀이 가려지는 문제 발생.
    - **해결**: `contentPaddingBottom` (픽셀 단위) 인자를 맵 가용 높이의 50%로 설정하여 SDK 차원에서 뷰포트를 위로 밀어올림.
- **이슈 2: 맵 제공자별 터치 이벤트 소비**
    - **현상**: 카카오 맵 등 특정 SDK에서 롱터치가 일반 터치와 간섭을 일으킴.
    - **해결**: `setOnMapLongClickListener` 내부에서 명확하게 상태를 변경하고, `isCreatingTodo`일 때만 녹색 핀을 그리도록 분기 처리.
- **이슈 3: ViewModel 초기화 NPE**
    - **현상**: `recentNames` 등 새로운 StateFlow를 읽을 때 초기 데이터 로드 전 UI가 그려질 경우 발생 가능성.
    - **해결**: `MutableStateFlow(emptyList())`로 안전하게 초기화하고 `loadTodos` 리스너를 통해 비동기 업데이트 보장.
- **이슈 4: 카카오 맵 SDK v2 리스너 명칭 불일치**
    - **현상**: `setOnMapLongClickListener` 메서드 부재로 인한 컴파일 에러 발생.
    - **해결**: SDK 분석 결과, 지면(Terrain)에 대한 롱터치는 `setOnTerrainLongClickListener` 메서드를 사용해야 함을 확인하여 수정.
- **이슈 5: 맵 제공자 간 LatLng 타입 충돌**
    - **현상**: 네이버(`com.naver.maps.geometry.LatLng`)와 카카오(`com.kakao.vectormap.LatLng`) 등 라이브러리 간 좌표 클래스 타입 불일치로 인한 데이터 전달 오류.
    - **해결**: 공통 상태 변수인 `creatingTodoLocation`을 카카오의 `LatLng`으로 통일하고, 네이버 콜백 등에서 명시적 좌표 변환(`from`)을 거치도록 로직 보완.

### [미결 이슈 / 피드백 대기]
- 연락처 선택 기능의 실제 연락처 연동(Permission 및 ContentResolver)은 현재 샘플 데이터로 대체되어 있으며, 추후 고도화 필요.
- 최근 할 일/메모 노출 시 정렬 기준(최신순 등)에 대한 정교한 정의 필요.

### [2025-12-23] 히스토리 통합 및 컨텍스트 생성 최적화
- **이슈 1: 히스토리 정보의 할 일 전환**
    - **현상**: 과거 이동 경로(History)를 기반으로 새로운 할 일을 만들고 싶은 사용자 니즈 발생.
    - **해결**: 모든 `UnifiedItem`에 대해 `onCreateTodo` 콜백을 구현하여 물풍선 터치 시 즉시 등록 레이어로 연결.
- **이슈 2: 레이어 타이틀 혼동**
    - **현상**: 기존 데이터 기반으로 등록 시 "만들기"라는 표현이 '수정'인지 '복사'인지 모호함.
    - **해결**: 등록 모드에 따라 타이틀을 "할 일 만들기"(신규)와 "할 일"(기존 기반)로 이원화함.
- **이슈 3: 히스토리 데이터 최적화**
    - **현상**: `UserLog` 테이블과 `PathItem` 테이블 이원화로 인한 관리 복잡성.
    - **해결**: 히스토리를 `TodoItem` (type: `"00"`)으로 통합 관리하고, 상세 경로는 `PathItem` 테이블에 `todo_id`로 연결하여 저장하는 구조로 개선.
