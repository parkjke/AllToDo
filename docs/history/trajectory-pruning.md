# Trajectory Pruning Research & Development Log

이 문서는 궤적 가지치기(Trajectory Pruning) 기술 연구 및 `TP-Android` 프로젝트의 발전 과정을 실시간으로 기록합니다.

## 2026-01-08: 연구 프로젝트 `TP-Android` 기반 구축

### 1. 프로젝트 목적
- 카카오맵 v2(벡터 엔진)을 활용한 대용량 궤적 데이터 렌더링 성능 검증.
- 궤적 가지치기(Pruning) 알고리즘의 안드로이드 최적화 및 시각화 연구.
- 미니멀한 UI 조작계([햄버거]-[내 위치]-[+][-][나침반]) 표준화.

### 2. 주요 달성 사항
- **환경 구축**: Gradle 8.13 및 AGP 충돌 해결, JVM Heap 4GB 증설.
- **인증 해결**: 카카오맵 v2 전용 App Key 설정 및 디버그 키 해시 등록 완료.
- **UI 레이아웃**: 상단 우측 조작계 배치 및 그룹별 여백(Spacer) 적용 완료.
- **커스텀 리소스**: `map_pin_00` 커스텀 내 위치 핀 연동 성공.
- **초기화 최적화**: `Application` 클래스(`TPApplication`) 기반의 SDK 정석 초기화 구조 도입.

### 3. 현재 상태

- [x] 상단 우측 조작 UI 적용 완료

## 2026-01-08: UI 고도화 및 위치 서비스 연구

### 1. 디자인 개선
- **버튼 스타일 변경**: 기존 화이트 바탕에서 프리미엄 블루(`0xFF007AFF`)로 변경.
- **시인성 강화**: 테두리에 `Gray 7` 컬러(1dp 보더)를 적용하여 지도 위에서의 구분을 명확히 함.
- **[UPDATE]**: 버튼 테두리 제거 (미니멀리즘 강화).

### 2. 위치 트래킹 구현
- **발견된 문제**: `startTrackingMode`라는 잘못된 API 호출로 인한 컴파일 실패.
- **해결 방안**: 카카오맵 v2의 정확한 API인 `TrackingManager.startTracking(label)`로 수정.
- **고도화**: `google-play-services-location` 의존성을 추가하고 `FusedLocationProviderClient`를 연동함.
    - 2초 간격(최소 1m 이동 시)으로 실시간 위치 업데이트 수신.
    - 수신된 위치로 `myLocationLabel`을 `moveTo` 시킴으로써 지도 위 실시간 움직임 구현.

### 3. 기능 확장 (궤적 리스트 오버레이)
- **UI 구현**: Gray 2/4 톤의 불투명 오버레이 레이아웃 구축.
- **컴포넌트**: `TrajectoryListOverlay` 컴포저블을 통한 이력 데이터 시각화.
- **[UI 세밀 조정]**:
    - 헤더("궤적 리스트" & [X])를 Gray 4 컨테이너 외부 상단으로 독립시킴.
    - 리스트 항목 배경 제거 및 항목 간 구분선(`HorizontalDivider`) 도입으로 미니멀리즘 강화.
    - **날짜 표시 간소화**: 년도를 제외한 월-일(MM-DD) 형식으로 변경하여 가독성 향상.
    - **단위 명칭 수정**: 모호한 "pts" 대신 직관적인 "**개**"로 변경 (예: 154개).
    - 리스트 창 상하좌우 여백 및 둥근 모서리(16.dp) 적용.
- **초기 시점 동기화**: 위치 권한 획득 및 첫 번째 위치 좌표 수신 시, 지도의 중심을 사용자의 현재 위치로 자동 이동. 연구 목적을 위해 **줌 레벨 18(상세 시점)**로 고정하여 정밀한 궤적 관찰 가능 토록 설정.

## 2026-01-09: 배터리 효율 분석 및 감도 제어 기술 통합

### 1. 배터리 소모 효율성 추적 시스템 (Battery-Aware Tracking)
- **도입 배경**: 궤적 기록 중 전력 소모가 중요한 지표임을 인식, 이동 기록과 배터리 상태를 연동함.
- **기술적 구현**:
    - **DB 스키마 확장**: `TrajectoryEntity`에 전력 필드(`begin_power`, `end_power`, `usage`)를 추가하여 세션별 분석 기반 마련.
    - **자동 분석 로직**: `BatteryManager`로부터 기록 시작/종료 시점의 잔량을 획득하고, 시간 경과에 따른 **초당 소모율(%/s)**을 계산하여 리스트에 시각화.
- **연구 결과**: 기록 정밀도(감도)와 배터리 소모량 사이의 상관관계를 사용자가 직접 분석할 수 있는 환경 구축.

### 2. 동적 위치 추적 감도 제어 (Dynamic Tracking Sensitivity)
- **기능 개발**: 사용자가 상황에 따라 추적 정밀도를 조절할 수 있도록 동적 설정 UI 도입.
    - **시간 기반**: [최소(X), 1초, 3초, 5초] 간격 조절.
    - **거리 기반**: [최소(X), 1미터, 3미터, 5미터] 간격 조절.
- **실시간 엔진 동기화**: `LocationRequest`를 실시간으로 재구성하여 지도 엔진이 즉각적으로 새로운 감도로 동작하도록 연동.

### 3. UI/UX 렌더링 최적화 및 프리미엄 마감
- **재생 커스터마이징 UI**:
    - 텍스트를 배제하고 **색상 배경과 점 아이콘(3pt/5pt/6pt)**을 활용한 시각적 버튼 그룹 구현.
    - 선택된 버튼에 2pt 다크 그레이 테두리를 적용하여 직관적인 피드백 제공.
- **녹화 버튼 디자인 정밀화**:
    - **[Purity Discovery]**: 마테리얼 `Icon` 컴포넌트의 내부 벡터 패딩(Vector Padding) 문제를 해결하기 위해, 아이콘을 직접 그린 **`Box`** 컴포넌트로 대체함.
    - 이를 통해 빨간색 영역과 흰색 테두리 사이의 미세한 간격을 완전히 제거하고 **완벽한 밀착(Perfect Flush)** 디자인을 구현함.
    - 테두리 두께 2pt 적용으로 시인성 강화.
- **레이아웃 정밀 정렬**:
    - **[Data Segregation]**: 배터리 효율(%/s) 표시를 날짜 하단에서 **삭제(휴지통) 버튼 바로 왼쪽**으로 이동하여 기록 데이터와 분석 데이터를 시각적으로 분리함.
    - "위치 추적 시간/거리" 등 레이블의 줄바꿈 방지(`maxLines=1`) 및 너비 고정(110.dp)을 통해 모든 설정 섹션의 수직 정렬을 완벽하게 맞춤.
    - 버튼 그룹에 **1pt Gray 5(0xFF9E9E9E)** 테두리와 구분선을 적용하여 정갈한 마감 구현.

### 4. 빌드 및 호환성 안정화
- **Compose Bom 대응**: 최신 `HorizontalDivider`를 사용할 수 없는 환경을 고려하여 `Divider`로 복구하여 빌드 이슈 해결.
- **리소스 가이드**: 누락되기 쉬운 `CircleShape` 등 형태 리소스에 대한 임포트 준수.
